# תוכנית ביצוע — מעבר ל-Postgres עצמאי

ענף: `migrate-to-self-hosted-postgres`
החלטה: **Postgres רגיל** (ללא Supabase כלל)

---

## מה מחליף מה

| היום (Supabase) | אחרי המעבר |
|---|---|
| Postgres מנוהל | **Postgres שלך** |
| PostgREST (`.from().select()`) | **SQL ישיר** דרך `pg` |
| Supabase Auth + MFA | **סשן משלנו** (cookie חתום + bcrypt) |
| Supabase Storage | **קבצים על הדיסק** |
| RLS עם `auth.uid()` | **הרשאות בשכבת השרת** |

## הארכיטקטורה מצילה אותנו כאן

הפרויקט בנוי עם seam אחד — `DataSource` ב-`lib/queries/types.ts`.
**אף רכיב באתר לא מייבא Supabase ישירות.** כל 74 המתודות עוברות דרך
`db` ב-`lib/queries/index.ts`.

המשמעות: אפשר להוסיף מימוש שלישי (`postgresDataSource`) לצד
`mock` ו-`supabase`, בלי לגעת בשום עמוד או רכיב.

**מה שכן נוגע בקוד מחוץ לשכבת הנתונים — 7 קבצים בלבד:**
```
app/(admin)/admin/login/actions.ts       התחברות
app/(admin)/admin/login/mfa/actions.ts   אימות דו-שלבי
app/api/admin/media-upload/route.ts      העלאת קבצים
lib/admin/dev-session.ts                 קריאת הסשן
lib/supabase/server.ts                   client
lib/supabase/middleware.ts               רענון סשן
lib/supabase/admin.ts                    service-role
```

## ⚠️ ההחלטה הכי חשובה — האבטחה

היום יש **61 מדיניות RLS** בבסיס הנתונים. הן שכבת ההגנה האמיתית:
מבקר אנונימי לא יכול לקרוא טיוטות, לידים או פרופילים — **גם אם יש באג
בקוד**.

ב-Postgres רגיל אין `auth.uid()`, ולכן המדיניות האלה לא יעבדו.

**שתי דרכים:**

**ב1 — להעביר את ההגנה לשכבת השרת** (מומלץ)
כל שאילתה עוברת דרך `postgresDataSource`, שמסנן לפי תפקיד המשתמש.
ה-DB לא חשוף לאינטרנט בכלל — רק האפליקציה מדברת איתו.

- ✅ פשוט להבין ולתחזק
- ⚠️ באג בקוד = דליפה. אין רשת ביטחון שנייה.
- 🛡️ מיטיגציה: כל הסינון במקום אחד, מכוסה בבדיקות

**ב2 — לשחזר RLS עם `SET LOCAL`**
להחליף `auth.uid()` במשתנה סשן שהאפליקציה מגדירה בכל בקשה.

- ✅ שומר על הגנה דו-שכבתית
- ⚠️ להמיר ולבדוק 61 מדיניות; שכחה של `SET LOCAL` = הכל חסום

**המלצה: ב1**, כי ה-DB לא יהיה חשוף החוצה. אם תרצה ב2 — אפשר להוסיף
בהמשך בלי לשנות את הקוד.

## ❓ החלטה פתוחה — MFA

היום יש אימות דו-שלבי דרך Supabase. לבנות אותו מחדש (TOTP + קודי גיבוי)
זו עבודה נפרדת ולא קטנה.

**האפשרויות:**
1. **לוותר** — התחברות עם סיסמה בלבד (מהיר, פחות מאובטח)
2. **לבנות TOTP** — תואם Google Authenticator (יום עבודה נוסף)
3. **לדחות** — לעבור בלי, להוסיף אחר כך

**צריך תשובה לפני שלב 3.**
